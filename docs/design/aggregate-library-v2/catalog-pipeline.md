# 聚合媒体库：本地刮削、媒体探测与海报墙

实施日期：2026-10-29，构建 6026。

## 实际链路

1. 已导入目录完整扫描成功，保存文件与文件源的关联。目录提示调整为“已导入：文件源名称”。同级/父子范围仍不允许重复导入。
2. 本地元数据队列连接 TMDB，按设备语言获取电影/剧集详情、评分、年份、题材、演职人员、海报与背景；剧集按季/集获取单集简介、剧照、日期和评分。
3. 独立探测队列调用现有 LucentAether 中的 `AetherEngine.probe`（FFmpeg libavformat/libavcodec 元数据接口）。不创建播放实例、不另行引入 FFmpeg 二进制。
4. 探测保存时长、视频编码、分辨率、帧率、动态范围、像素/颜色标记和音轨、字幕轨道，复用详情页媒体信息卡片，并为播放路由提供已知特征。
5. SQLite 保存结构化元数据、探测结果和各项尝试状态。重启从本地记录恢复；旧基础元数据按已知 TMDB ID 升级，不必重新猜测匹配。
6. 首页海报墙按 TMDB 类型与 ID 聚合：整部剧一张海报，同电影多个文件作为版本计数；继续观看保留具体集数与文件播放进度。未匹配文件单独列出并保留手动匹配入口。

## 队列与失败处理

- 目录扫描、TMDB、FFmpeg 和图片预热分别排队。FFmpeg 同时只处理一个文件，在 utility 线程执行同步探测。
- 每次 FFmpeg 探测使用 16 MiB 输入预算、20 秒协作式时间预算和可取消 token。原始网络请求的结束仍取决于协议客户端是否及时响应取消/超时；这不是所有 NAS 的绝对墙钟上限。不会为了刮削下载完整影片。
- 本地文件在探测期间持有 security-scoped bookmark；SMB/WebDAV/网盘复用已有 Range 读取桥接，结束时关闭代理与访问权限。Emby/Jellyfin/Plex 不进入本地探测队列。
- 无 TMDB 令牌时仍可扫描和探测，页面明确提示需要配置令牌。
- 精确标准化标题、原始标题及电影年份参与匹配。存在歧义时留在待匹配，不按搜索热度猜测。
- TMDB 网络失败保留文件和旧元数据，15 分钟后可重试；单集补充资料失败等待 1 小时，未匹配条目等待 1 天。实际重试由下次前台调度或设置中的重试入口触发，不保证 iOS 后台持续执行。
- 探测失败保留条目、错误与重试时间，1 小时后可再次调度；设置中的“重试刮削与媒体探测”可立即重试失败项。已成功的探测不因普通目录重扫重复请求。
- 首屏最多 24 张海报独立预热，其余图片在可见时通过现有 7 天图片缓存按需加载；图片失败不阻断元数据与探测队列。
- 文件源停用/移除后不会产生新的处理任务，返回的探测结果也会检查条目仍在启用范围内。已有观看记录和下载不被重建。

## 参考来源与差异

- [VidHub 文件源说明](https://zh.vidhub.okaapps.com/file-sources/)：参考文件名识别、获取海报与资料后归纳媒体库的用户流程。
- [网易爆米花官方 App Store 说明](https://apps.apple.com/cn/app/id6480252695)：参考本地/NAS/网盘资源识别、海报墙的产品组织。没有声称了解或复制其内部实现。
- [Jellyfin FFProbeVideoInfo](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Providers/MediaInfo/FFProbeVideoInfo.cs)：参考将技术信息探测与在线资料获取分开，并持久化媒体流、时长与画面属性。未复制 GPL 业务代码；Lucent 使用 Swift 与现有 SQLite/Range 网络层。
- [AetherEngine+Probe](https://github.com/superuser404notfound/AetherEngine/blob/61250c9f9fe1624d4ac4b2d069fb0bdaca2cc213/Sources/AetherEngine/AetherEngine%2BProbe.swift)：使用已经集成的同平台 LGPL API，包括 ProbeLimits、ProbeCancellation、SourceProbe。保持动态框架隔离，避免与 MPVKit 的另一套 FFmpeg ABI 混链。
- [TMDB 电影详情](https://developer.themoviedb.org/reference/movie-details)、[单集详情](https://developer.themoviedb.org/reference/tv-episode-details)：详情接口按设备语言请求，演职人员通过 append_to_response 获取。

## 验证与边界

`python3 scripts/verify-local-catalog.py` 运行生产模型、命名解析器、匹配策略和 TMDB 客户端，使用 URLProtocol 内存夹具，覆盖年份/同名歧义、原始片名、中文季集、详情和单集解析、音视频字幕持久化、本地详情适配、剧集合并和旧记录兼容。

不启动应用、不操作真机/模拟器，不将构建或离线夹具通过描述为真实网盘/FFmpeg 运行已验证。用户应在真机导入一个含电影及多集剧集的目录，观察扫描、刮削、探测分别完成；重启后检查海报墙、整剧分组、继续播放及媒体信息卡片。

当前技术信息的容器名称来自文件扩展名（探测 API 未提供实际容器字段）；不会填造未知视频码率或文件大小。成功探测结果不按文件内容哈希自动失效；同路径替换文件后的强制重新探测、NFO 读取等不属于本次实现。

## 6028：媒体信息探测开关

设置 → 聚合媒体库 → 扫描与匹配新增“FFmpeg 媒体信息探测”，缺少已保存选择时默认关闭，后续记住用户选择。默认扫描、前台恢复、TMDB 自动刮削及重试入口均不会绕过该开关启动文件探测。

关闭时取消当前探测，通过现有 AetherEngine ProbeCancellation 收尾，并停止后续调度；保留已经成功探测的信息。快速关闭再开启会等旧 reader/代理收尾后再排队，避免双任务。被取消的尝试不占失败重试冷却时间。开关不影响播放器起播时必要的格式识别。

验证仅构建和静态检查，不自动启动应用。用户可在真机验证默认关闭、扫描不探测、开启后补齐、处理中关闭及快速关闭/开启。

### 6029：80 个待匹配文件的即时结束问题

- 从真机 SQLite 只读核对：80 个文件分属“我们的歌 2019”（60）和“我想和你唱 2016”（20），均为旧状态“待手动匹配”。旧逻辑把年份留在查询标题中；一次否定结果会将整档节目所有文件延后一天，随后将空的到期队列误报为完成。
- 参考 Kodi 剧集命名约定（https://kodi.wiki/view/Naming_video_files/TV_shows），仅借鉴标题/年份分离设计，未复制代码。`CatalogMatching.seriesQuery` 支持空格分隔年份及中英文括号年份；保留原目录身份键，既有索引无需重新扫描；年份用于候选首播年份的严格校验，不放宽歧义匹配。
- 手动重试若碰上正在运行的批次，会登记一次后续重试，等批次结束再清除冷却时间，避免旧请求覆盖重试。重复点击合并，仍保持单个网络队列。
- 完成提示区分：待执行、未匹配、已匹配但详情缺失、全部匹配。负匹配记录区分零搜索结果和无唯一标题/年份候选。FFmpeg 探测开关保持默认关闭。
- 离线回归覆盖真机两种目录名、括号年份和数字片名保护；构建安装不代表已验证真实 TMDB 返回或节目各季的单集编号，需用户重新刮削确认。

6026/6029 的“唯一标题+严格年份”自动匹配入口已由独立 Swift `TMDBCatalogRecognizer` 替代。当前采用 MoviePilot 的分阶段识别、年份容差、候选排序、别名翻译、季年份与类型回退规则，说明及对照测试见 [tmdb-recognition.md](tmdb-recognition.md)。`CatalogMatching.best` 仅保留为旧的纯函数校验工具，不再是自动刮削入口。

### 6032：播放时保存媒体信息

- AVPlayer、AetherEngine、MPV 回写各自已经读取的媒体信息，不启动第二个探测器，不修改默认关闭的扫描 FFmpeg 开关。
- 保存来源视频编码、FourCC（尤其 `hev1`）、分辨率、动态范围、容器、时长，以及可用的音轨/字幕轨道。MPV/Aether 回写输入轨道，AVPlayer 从当前 asset 读取。
- 使用 `LibraryStore.recordPlaybackMedia` 持久化到现有 SQLite；视频信息完整到可用时才建立技术记录，缺失观察值保留旧值，语义相同的观察不会重复写库。
- 切换内核时音轨/字幕索引可能改变，以当前观察到的轨道类型替换对应列表，避免混合 AVTrack ID 与 FFmpeg stream index 而重复。外部影视服务器条目仍使用服务器元数据。
- 拖动定位/缓冲/首次加载使用同一加载圈：固定 80 点圆形容器、large circular 白色指示器，统一出现/消失动画。
- `scripts/verify-playback-metadata.py` 离线执行生产持久化方法，检查重复写入、轨道替换、hev1 标记、存档解码与服务器隔离；不启动应用。
