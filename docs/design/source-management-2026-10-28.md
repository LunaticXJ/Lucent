# 片源模块设计与实现（2026-10-28）

## 产品边界

保留两个入口：

- **影视服务器**：Emby、Jellyfin、Plex。服务器提供元数据、分类和观看记录；卡片点击后切到该账户的首页，不在片源页复制媒体浏览界面。同地址的不同账户继续独立保存。
- **聚合媒体库**：一个本机媒体库，由选中的文件源组成。关闭来源开关仅隐藏入库内容，文件源仍能浏览；本轮不增加独立的“媒体库管理”页面，扫描和匹配配置继续放在设置中。

右上角只保留统一加号。添加选择器按服务器、文件源、局域网设备分类；不恢复单文件上传、网络视频地址等此前移除的入口。

## 参考及实现差异

1. [VidHub 官方文件源说明](https://zh.vidhub.okaapps.com/file-sources/)：参考文件源启用、重命名、单源扫描，以及媒体库/影视服务器的分工。
2. [VidHub 文件源操作说明](https://zh.vidhub.okaapps.com/use-file-source/)：参考目录浏览、文件观看标记与下载入口。Lucent 的移除操作只移除本机来源配置及关联记录，不实现远端原文件删除或重命名。
3. [SenPlayer 官方介绍](https://senmuse.com/)：参考不同类型资源的分类组织和媒体服务器直连方式。未把宣传中的协议、网盘和播放能力视为 Lucent 已实现的能力。
4. 开源实现参考：本机 Yattee 的 `Views/Settings/InstanceAccountsSection.swift`、`Core/AccountRemoval.swift`。参考账户标识与凭据隔离、操作确认和关联数据清理思路；未复制 AGPL 代码。
5. SMB 沿用项目已固定的 SwiftSMB **3.3.1**（`107c0909`），使用同步 `listDirectory`，在 utility/userInitiated 后台任务中列目录，退出前断开连接；不新引入 SMB 实现。

商业播放器仅作为公开功能及界面参考，不复用其私有代码或图像资产。服务器继续使用项目中已有的官方品牌图标。

## 本轮实现

| 区域 | 交互与功能 |
|---|---|
| 片源首页 | 保持“片源”标题；影视服务器在前；记住所选分栏；统一加号；按当前分栏下拉刷新 |
| 服务器列表 | 自适应卡片；名称、影片数、剧集数、域名及账户；显示当前首页来源；显示检测中、成功、暂不可用、尚未检测 |
| 服务器状态 | 从实际统计请求得出结果，不默认显示绿色；本页会话内复用 5 分钟的检测结果；合并同一服务器的重复请求；长按可强制重试，不弹测速提示 |
| 新增和编辑服务器 | 支持完整 URL 粘贴并拆分协议、域名、端口和路径；空端口使用协议默认值；连接地址预览；保留多账户登录与修改用户名后重建账户的既有逻辑；Plex 提供授权网站链接 |
| 聚合仪表盘 | 电影数、剧集数、文件数、最近刷新时间、已加入/总来源数、扫描状态；不增加管理页跳转 |
| 文件源目录列表 | 来源类型、视频数、扫描/失败/仅浏览状态及入库开关；长按重命名、编辑凭据、扫描或移除 |
| 来源重命名 | 本地文件夹、SMB、WebDAV、网盘均可重命名；SMB/WebDAV 新增可选 displayName，兼容旧配置 |
| 移除 | 使用稳定的来源 ID 和确认弹窗；提示移除范围；移除首页当前服务器时重置首页选择 |
| 本地目录 | 搜索当前目录、名称排序、刷新和关闭；直接播放时使用已保存条目或注册条目，避免每次生成不同 ID 丢失续播记录 |
| SMB/WebDAV 目录 | 实时读取当前目录，不要求先全盘扫描或开启入库；目录优先、搜索、排序、刷新、错误重试；文件可播放、收藏、标记观看或下载 |
| 网盘 | 保留现有各服务授权方式，分类入口默认 115；切换服务清空旧授权草稿；名称可缺省为服务名称；明确展示扫描索引和刷新入口 |
| 播放历史 | 直接浏览打开本地/SMB/WebDAV 文件时复用同一 location 的持久条目；未加入媒体库的来源不会因单文件播放被自动启用 |

服务器统计读取失败可能是权限或接口差异，因此显示“暂不可用”，不把它断言为整个服务器离线。保留已取得的统计数据。

## 性能与状态

- 目录读取与全量扫描分开：浏览 SMB/WebDAV 不递归扫库，不触发全库 TMDB 匹配。
- SMB 同步 I/O 在后台执行；WebDAV 采用异步 PROPFIND Depth:1，超时 25 秒。
- 页面离开后丢弃过期结果；SMB 的阻塞请求本身受 SDK 20 秒连接配置约束，尚未增加主动中断接口。
- WebDAV 过滤非直属子项、重复项、跨源/端口条目和父目录路径；处理原始中文与现有百分号转义混用导致的二次编码。
- 先完成统计再补用户名，避免用户名变更使 SwiftUI 取消首个统计任务；编辑完成后刷新对应服务器统计。

## 明确的能力边界

- FTP/NFS 尚未接入，不显示无法工作的连接入口。
- 网盘仍以现有 API 的递归视频索引浏览；不是所有网盘都支持逐级实时目录和完整原始文件管理。
- 尚未实现来源批量管理、服务器多线路自动切换、扫描目录排除规则、后台扫描任务恢复和远端文件改名/删除。这些需要独立设计和协议适配。
- 云盘首次添加沿用既有授权与索引流程，大型网盘可能仍需较长时间；本轮不把它包装成瞬时连接。
- 本轮没有新增来源凭据云同步。Personal Team 安装包不带 iCloud entitlement。

## 检查和交付

- `python3 scripts/verify-source-management.py`：从实际代码提取基础模型和 WebDAV 实现，使用内存 URLProtocol 响应检查 URL 拆分、非法端口、旧配置兼容、名称持久化、中文/空格路径、去重、直属目录与来源边界。不会访问用户服务器。
- iOS Debug 构建和真机安装；不启动应用，不进行模拟器、截图或播放自动回归。
- 手动验证：深浅主题和大字体布局；添加/编辑三种服务器；同地址多账户；切换首页来源；各类型长按操作和移除确认；开关对媒体库的影响；SMB/WebDAV 未扫描时的浏览、中文目录播放、断网重试；网盘授权和索引刷新。
